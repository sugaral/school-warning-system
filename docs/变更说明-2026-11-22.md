## 二、P0 缺陷修复（提交 `32309ad`）

### 1. 报表导出一直显示“生成中”

- **现象**：报表页所有新生成的记录都停在“生成中”，不出现下载按钮；实际文件已生成（`/admin/reports/download/116` 返回 200 + 16 KB xlsx）。
- **根因**：状态枚举不一致 —— 后端 worker 写 `status='success'`，前端只把 `'completed'` 视为完成；历史数据用的又是 `completed`。附带的第二个问题是下载文件名被硬编码成 `.csv`（实际下发 xlsx）。
- **改动**：
  - `backend/src/reports/export-processor.service.ts`：完成态统一写 `completed`；
  - `backend/src/reports/reports.controller.ts`：下载判定兼容 `completed | success`，历史接口文件名改 `.xlsx`；
  - `admin-frontend/src/pages/Reports.vue`：抽出 `isReportDone / isReportFailed`，新增“生成失败”态，下载文件名按真实类型命名。
- **验证**：新任务 `id=117` 落库 `completed`；页面“已完成 2 / 生成中 0”，两行均可下载。

### 2. 预警统计出现“未知学院”

- **现象**：`预警统计-1` 的「院系处置表现」出现一行“未知学院 / 31 学生 / 0 预警”。
- **根因**：`stats.controller.ts` 只用“有预警的 org”预置 `orgMap`，没有预警的学院走到 fallback 名称。
- **改动**：组织名改为「有预警 ∪ 有学生」的并集。
- **验证**：接口现在返回 5 个真实学院（人工智能 31/31、文学院 31/0、经管 30/0、物电 30/0、化工 20/0）。

### 3. 开发模式下 SPA 深链接变成 JSON

- **现象**：直接刷新/收藏 `/warnings`、`/students`、`/attendance` 等路由，页面变成后端返回的 `401 Missing authentication token` JSON。
- **根因**：`admin-frontend/vite.config.ts` 把与前端路由同名的前缀全部代理给后端。
- **改动**：抽成统一的 `apiProxy()`，按 `Accept: text/html` 放行给 `index.html`（与生产 nginx 的 `try_files` 逻辑一致），XHR 仍走后端。
- **验证**：6 个路由整页访问均返回页面并正常渲染（不再出现 JSON）。

### 4. 表格列宽塌缩，内容被截成“计…/2026-11-…”

- **根因**：自适应逻辑为了“消灭滚动条”把文本列压到表头宽度；且只统计 `td` 内边距，漏掉 el-table `.cell` 的 24px，导致测量值偏小。
- **改动**（`admin-frontend/src/lib/responsive-table.ts`）：
  - 测量时计入 `.cell` 的水平内边距；
  - **内容放得下才铺满，放不下交给 el-table 横向滚动，不再压缩内容列**（覆写列宽还会破坏固定列定位）；
  - `Attendance.vue` 的课程/班级补 `show-overflow-tooltip`。
- **取舍**：签到明细这类 9 列宽表会横向滚动（操作列需要滚动查看），换取内容完整可读。若要求单屏看全，需要做页面级精简（合并“签到窗口”、压缩统计列）。

## 三、P1 问题修复（提交 `c10d557`）

- 删除旧系统遗留的 **47 张表**：`EDU_*`(14)、`SYS_*`(12)、`DEV_*`(11)、`CLIENT_*`(4)、`BIZ_NOTICE`、`AUTH_THIRD_USER`、`GEN_*`(2)、`MOBILE_RESOURCE`。

### 7. 报表历史几乎为空

- **根因**：历史接口固定 `creator_user_id = 当前用户`，换管理员后只能看到自己创建的记录（库内 111 条只返回 1 条）。
- **改动**：改为**按数据范围可见** —— 全校范围看全部；学院/班级/本人范围看“自己创建的 + 范围内他人创建的”。下载与删除的权限校验统一为 `canAccessExportJob()`，避免“看得到但点下载 403”。
- **前端**：新增「创建人」列，接口返回 `creatorName / isMine`。
- **验证**：接口返回 50 条（`total=111`），可见 `25软1班主任` 等旧账号的历史，下载正常。

### 8. 两份 `.env`

- **根目录 `.env` 成为唯一配置源**：`DATABASE_URL=…@127.0.0.1:3307`、`REDIS_URL=redis://127.0.0.1:6380`、`MINIO_ENDPOINT/PORT=127.0.0.1:9100`（本地后端用宿主映射端口）。
- **容器内改用服务名**：`docker-compose.yml` / `docker-compose.prod.yml` 里把连接串固定为 `mysql:3306`、`redis:6379`、`minio:9000`，不再从 `.env` 取；`docker compose config`（dev/prod）校验通过。
- **后端读取**：`backend/src/app.module.ts` 的 `envFilePath` 增加 `../.env`；删除 `backend/.env` 与 `backend/.env.example`。
- **Prisma CLI**：只认 `backend/.env`，因此 `start.ps1` 会自动创建一个指向根 `.env` 的**硬链接**（同一份内容，改一处两边同步，不会漂移）。
- `.env.example` 同步更新，并注明“不要再创建 backend/.env”。

## 七、回滚方法

```bash

git revert c10d557   # 旧表清理 / 报表历史 / .env
git revert 32309ad   # 四个 P0 修复

rm backend/.env && cp .env backend/.env
```
