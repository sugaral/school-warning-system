## 二、P0：学生/教师数据范围越权

### 2.1 现象

在本地还原库上，用真实 token 调用管理端学生接口：

| 账号 | 角色/范围 | 修复前 `GET /admin/students` |
|---|---|---|
| 教师 800 | teacher / self | `total=152`，返回全校学生 |
| 学生 679 | student / class 3 | `total=31`，返回同班全部同学 |
| 班长 809 | class_monitor / class 3 | `total=31` |

返回字段包含 `student_no`、`name`、`mobile`、`wx_openid` 等敏感信息；教师 800 还可通过 `GET /admin/classes` 看到全校 5 个班级。

### 2.2 根因

1. `DataScopeInterceptor` 直接按 `user_roles.scope_type` 计算范围。学生/班长的 role 行是 `class`（记录“所在班级”），于是被当作“可看全班”。
2. 普通教师 role=teacher/self，但没有学生档案，`studentIds` 计算为 `undefined`。`students.admin.controller.ts` 的过滤条件是 `if (dataScope.studentIds)`，`undefined` 直接跳过，退化为“无过滤 = 全校”。
3. `classes.admin.controller.ts` 对 `self` 范围没有分支，同样退化为无过滤。

### 2.3 修复

- `backend/src/rbac/data-scope.interceptor.ts`
  - 纯 `student` / `class_monitor` 账号强制收敛为 `type=self`，只允许本人；
  - `collegeIds` / `classIds` / `studentIds` 不再返回 `undefined`，统一返回数组，空数组明确表示“0 行”。
- `backend/src/students/students.admin.controller.ts`
  - 学生列表改用已有的 `buildStudentScopeWhere()`（self/class/college 都有 `[BigInt(-1)]` 兜底）；
  - `students/classes/list` 对 self 无学生档案、class/college 空数组补 `id in [-1]`，不再退化为全校。
- `backend/src/classes/classes.admin.controller.ts`
  - class/college 使用 `?? []`；
  - self 显式 `where.id = { in: [] }`，普通教师不再看到全校班级。

### 2.4 修复后验证

| 账号 | 修复后 `/admin/students` | 修复后 `/admin/classes` |
|---|---|---|
| 教师 800 | 0 | 0 |
| 学生 679 | 1（本人） | 403（无 class:read） |
| 班长 809 | 1（本人） | 0 |
| 班主任 804 | 31（本班） | 本班 |
| 副院长 806 / 学工 807 | 31（本院） | 本院 |
| 教务 808 / 管理员 647 | 152（全校） | 全校 |

跨班/跨院学生详情（IDOR）5 项全部 403；`export-accounts` 权限 7 项符合预期。

## 三、P1：宽表「操作」列被裁切

### 3.1 现象

- `/attendance` 操作列 `cellWidth=88`、`contentWidth=336`，只显示“查看二维码”，其余按钮被 `.cell` 的 `overflow:hidden` 裁掉；横向滚动也看不到，功能不可达。
- `/warnings` 操作列 `111 vs 118`，最后一颗按钮差 7px。

### 3.2 根因

`admin-frontend/src/lib/responsive-table.ts` 在空表首轮渲染时按表头写死窄列宽；数据到达后，`sumNeeded > viewportWidth` 分支直接 `return`，没有撤销第一轮写入的列宽，导致窄列宽永久残留。

### 3.3 修复

- `responsive-table.ts`
  - 空表（`bodyRows.length === 0`）不再写列宽，先 `resetAppliedColumnWidths()` 并返回；
  - 超宽时撤销脚本写入的 col/th/table 宽度，交还 el-table 的声明列宽 + 横向滚动；
  - 操作列预留 16px 测量误差，且不小于声明列宽；
  - 图表/进度条/图片按真实渲染宽度测量；**SVG 是 `SVGElement`，不能用 `instanceof HTMLElement` 过滤**（这是 trend sparkline 测宽为 0 的根因）；
  - 新增 `readDeclaredColumnWidth()`，避免脚本把声明宽度压小。
- `admin-frontend/src/pages/Warnings.vue`：操作列 `width 140 → 150`。
- `admin-frontend/src/pages/system/SystemStats.vue`：趋势列固定 `width=180`；状态列 `min-width 100 → 130`。

### 3.4 修复后验证

- `G3 操作列裁切`：0 处
- `G4 图表裁切`：0 处
- `G-system-stats 截断`：0 处
- `/attendance` 操作列恢复 336px，横向滚动正常，四个按钮完整可点
- 学生列表“微信绑定”不再截断；班级/邮箱改为带 tooltip 的省略显示

## 四、P2：`npm test` 无法运行

### 4.1 现象

```text
FAIL src/shared/file-access.util.spec.ts
SyntaxError: Cannot use import statement outside a module
```

仓库已安装 `jest` / `ts-jest` / `@types/jest`，但 `backend/package.json` 没有 Jest 配置，TS 测试文件没有被转换。

### 4.2 修复

在 `backend/package.json` 增加：

- `rootDir: src`
- `testRegex: .*\.spec\.ts$`
- `transform: ts-jest`（inline tsconfig：commonjs / ES2020 / decorators / strict）
- `testEnvironment: node`

### 4.3 验证

`npm test` → `1 passed, 6 tests passed`。
